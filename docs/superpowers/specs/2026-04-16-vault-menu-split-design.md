# 지식베이스 메뉴 분리 설계 (탐색/추가)

## 1) 배경
- 현재 `지식베이스(/vault)` 단일 화면에 탐색, 검색, 파일 뷰어, AI 채팅, ingest(파일/URL/배치), lint가 모두 포함되어 있다.
- 기능 밀도가 높아 신규 사용자가 "어디서 무엇을 해야 하는지" 즉시 이해하기 어렵다.
- 사용자 목표는 다음 두 가지다.
  - 탐색과 추가를 분리해 화면을 단순화
  - 메뉴 이름만으로도 기능 의도를 이해 가능하게 개선

## 2) 목표와 비목표
### 목표
- 지식베이스 메뉴를 `탐색`과 `추가` 하위 메뉴로 분리한다.
- AI 채팅은 `탐색` 화면에서만 제공한다.
- 기존 기능은 유지하되 화면 책임만 명확히 분리한다.

### 비목표
- ingest 파이프라인 백엔드 로직 자체의 대규모 변경
- 검색/랭킹 알고리즘 개선
- IA 개편과 무관한 전면 UI 리디자인

## 3) 최종 IA(정보 구조)
- 상위 메뉴: `지식베이스`
- 하위 메뉴:
  - `탐색` (`/vault/explore`)
  - `추가` (`/vault/ingest`)
- 호환 라우트:
  - `/vault` 접근 시 `/vault/explore`로 리다이렉트

## 4) 화면 책임 분리
### 4.1 탐색 화면 (`/vault/explore`)
- 포함:
  - 검색
  - 새로고침
  - 인덱스 상태 배지
  - 폴더 트리 / 파일 목록 / 파일 뷰어
  - AI 채팅(인용 기반 응답)
- 제외:
  - 파일 추가/URL 추가/배치 ingest 버튼
  - ingest 결과 패널
  - ingest 중심 운영 액션

### 4.2 추가 화면 (`/vault/ingest`)
- 포함:
  - 파일 추가
  - URL 추가
  - 배치 ingest
  - ingest 처리 상태/결과/경고
  - KB Lint, 인덱스 새로고침
- 제외:
  - 폴더 트리 / 파일 뷰어
  - AI 채팅

## 5) 라우팅/네비게이션 설계
- `frontend/src/main.tsx`
  - 신규 라우트 추가:
    - `/vault/explore`
    - `/vault/ingest`
  - `/vault`는 `Navigate`로 `/vault/explore` 리다이렉트
- `frontend/src/components/Layout.tsx`
  - 기존 단일 링크 `지식베이스(/vault)`를 아코디언으로 변경
  - 하위 링크 `탐색`, `추가` 제공
  - 활성 상태는 하위 경로 기준으로 표시

## 6) 프론트 구조(컴포넌트/상태)
### 6.1 페이지 구조
- `VaultExplorePage` (신규)
- `VaultIngestPage` (신규)
- 필요 시 공통 레이아웃/알림을 위한 `VaultShell` 도입

### 6.2 상태 훅 분리
- `useVaultExplore`:
  - 폴더 로딩, 검색, 파일 선택, 새로고침
  - 탐색 화면 busy/error 상태 관리
- `useVaultIngest`:
  - ingest 실행, 배치 실행, lint 실행, 결과 피드백
  - 실행 중 잠금 및 경고 표시

## 7) API 사용 매트릭스
### 탐색 화면 전용
- `GetVaultStructure`
- `GetVaultFile`
- `SearchVault`
- `RetrieveVaultContext`
- `RefreshVault`

### 추가 화면 전용
- `IngestKnowledgeSource`
- `IngestKnowledgeBatch`
- `RunKnowledgeBaseLint`
- `RefreshVault`

## 8) 사용자 흐름
### 탐색 중심 흐름
1. `탐색` 진입
2. 파일 검색/선택/열람
3. AI 채팅으로 질의(인용 확인)

### 추가 중심 흐름
1. `추가` 진입
2. 파일/URL/배치 ingest 실행
3. 결과 및 경고 확인
4. 필요 시 `탐색으로 이동` CTA로 검증

## 9) 오류/상태 UX 원칙
- 피드백 타입 표준화: `info | success | error`
- 액션 동시 실행 방지: ingest/lint/refresh 중복 실행 잠금
- 오류 메시지는 사용자 행동 문구 포함
  - 예: "추가는 완료되었지만, 탐색 목록 갱신에 실패했습니다."
- 빈 상태 문구를 화면 목적에 맞게 분리
  - 탐색: 검색 결과/파일 없음
  - 추가: 소스 입력 안내

## 10) 마이그레이션 계획
1. 라우트/사이드바 메뉴 분리
2. 기존 `VaultPage`에서 탐색/추가 UI를 각각 이동
3. 공통 피드백 컴포넌트 정리
4. 회귀 테스트 추가
5. 배포 후 사용성 피드백 반영

## 11) 테스트 전략
- 라우팅 테스트: `/vault -> /vault/explore`
- 메뉴 테스트: `지식베이스 > 탐색/추가` 노출 및 active 상태
- 기능 테스트:
  - 탐색에서 채팅 노출
  - 추가에서 채팅 비노출
  - 추가 액션(파일/URL/배치/lint) 정상 동작
- 회귀 테스트:
  - 기존 파일 탐색/뷰어 동작
  - 기존 ingest 결과 피드백/오류 처리 동작

## 12) 결정 요약
- 메뉴 구조는 `탐색/추가` 2분할로 확정
- AI 채팅은 `탐색`에만 배치
- 목적 중심 분리로 학습 비용을 낮추고, 기존 기능은 유지한다
